## 1. 目标与设计依据

### 1.1 三端职责

| 界面 | 使用者要完成的事 | 主要内容 | 不承担的职责 |
| --- | --- | --- | --- |
| 测试手机 App | 看清发生了什么、定位问题、导出证据 | 状态来源、命令结果、设备、会话、媒体、日志 | 不成为第二个采集状态机，不用模拟成功替代设备结果 |
| 日常手机 App | 找到、回放和管理一条真实记录 | 音频/照片/原厂视频、地点、同步、处理结果 | 不把工程日志铺在首页，不负责眼镜离线采集生命周期 |
| 眼镜 App | 一眼知道当前状态，直接控制本应用隐私与恢复 | 边缘 HUD、电量、隐私进度条 | 不做手机式多页管理，不用页面存活维持采集 |

**已确认：** 眼镜是单色绿屏；UI 只能依靠明度、线条、形状和文字。保留原厂拍照/录像，原厂视频后续须导入本 App 保存/回放；不自研录像引擎。关闭本 App 页面与进入本 App 隐私是两件事。

### 1.2 如何借鉴 Apple

采用内容优先、稳定导航、直接操作、及时反馈、克制动效和可访问性；Android 手机沿用本平台字体、返回、权限与文件选择习惯。眼镜不照搬 Vision Pro 的浮窗、毛玻璃、大卡片或眼手追踪。

| 依据                                                                                                                              | 本项目落实                                       |
| ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| [Apple · Designing Fluid Interfaces](https://developer.apple.com/videos/play/wwdc2018/803/)：响应与可中断操作                            | 输入立即反馈；提交前可以反向/取消；动画不能阻塞停止请求，也不能决定业务状态。     |
| [Apple · Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars?changes=l_1__4&language=objc)：稳定的一级导航 | 手机导航按“记录 / 同步 / 设备”组织；“上传”“导入”是操作，不伪装成导航页签。 |
| [Apple · Color](https://developer.apple.com/design/human-interface-guidelines/color?changes=_5_2)：重要信息不只靠颜色                     | 手机也用文字/符号区分异常；眼镜完全按单色设计，重要状态不用暗灰隐藏。         |

这里引用的是设计原则；具体布局、参数和 RV101 行为是本项目建议或待验证事项，不声称是 Apple 官方规格。

Android 适配依据：[眼镜设计原则](https://developer.android.com/design/ui/ai-glasses/guides/foundations/design-principles)强调透明显示与现实背景竞争，信息应简短且适合一瞥；[手机可访问性](https://developer.android.com/guide/topics/ui/accessibility/apps)建议触控目标至少 48×48dp。前者只作视觉原则参考，不证明 RV101 支持 Android XR 接口；后者不换算成眼镜显示尺寸。

### 1.3 公共视觉与反馈规则

| 项目 | 手机设计建议 | 眼镜设计建议 |
| --- | --- | --- |
| 信息层级 | 页标题 → 主要内容 → 状态/辅助信息；同一页一个突出主操作 | 真实状态优先；左下固定三行，控制行切换说明/进度/原因 |
| 排版初值 | 系统中文字体；页标题 26–28sp、正文 16sp、辅助 13–14sp；内容边距 16dp，间距以 8dp 为基本单位 | 先采用清晰中等字重；按实际视野和佩戴调整字号/安全边，不从截图像素换算视角 |
| 可访问性 | 触控区至少 48×48dp；图标可小于触控区；支持系统大字、读屏标签、深浅模式；图标均有名称 | 高亮文字/端点与中亮轨道，低亮仅作装饰；焦点不靠颜色，不用整块高亮背景 |
| 材质 | 平整分组和留白为主；仅导航/短操作面板需要层次，避免每行套卡片 | 不使用大片底板、模糊、阴影；黑色像素不被解释为能遮住现实的黑色面板 |
| 动效 | 普通进入/反馈初值 120–200ms，少量淡入/位移；系统减少动态效果时用静态/淡入 | 仅进度跟随和短反馈；不弹跳、不闪烁、不做循环波形；业务失败信息保持可读 |
| 等待 | 有实际总量才显示百分比；总量未知显示步骤名；完成必须等待真实结果 | 手势进度只表示操作完成度；绝不表示“已停止 70%” |
| 失败 | 就地显示“哪一步失败＋可做什么”，保留用户上下文；已完成步骤不因后续失败退回未完成 | 固定位置显示短原因；停止未确认、状态未知不能几秒后消失成正常状态 |

字号、间距、动效数值是待样稿/佩戴核验的初值，不是本轮测量结果；手机最小触控区沿上述 Android 依据。极简不能靠缩小文字、降低必要文字对比度或缩小触控区实现。装饰动画可中断；已经提交的停止命令不能靠反向动画撤销。

## 2. 日常手机 App：内容与页面

### 2.1 导航与通用布局

**2026-09-24 日常端候选修订（用户要求Apple式精致感，具体成品待审阅）：** 系统字体，页标题28sp/分组20sp/正文16sp/辅助14sp；20dp内容边距。底部为带文字的线性图标导航，当前入口用颜色及字重共同标识；筛选使用轻量分段样式，触控区至少48dp。复用Android原生ripple/返回/滚动与现有tab状态，不引入动效库或仿iOS系统控件。只有一个页标题，空库使用真实空状态；同步四步保留未知/未接入，工程协议名留测试端。手机测试输入明确标记，连接状态不代表实际录音确认。测试端未作整套视觉重设计，眼镜样稿保持已接受版本。

底部三个带文字的稳定入口：**记录 / 同步 / 设备**。默认打开记录；每个入口保留滚动位置。设置从设备页进入。详情采用层级返回，返回后保留原筛选与列表位置；系统返回优先关闭当前弹层，再回上页，不触发采集停止。

有正在回放的音频时，迷你播放器固定在底部导航上方；列表/网格预留两者及系统安全区的实际高度，最后一项可完整滚出。进入完整音频详情后只显示该页播放器，不再叠一套迷你播放器。长标题可换行或省略非关键名称，状态与控制不能挤掉；大字模式随实际高度重新留位，不能覆盖最后一排照片。

记录页是内容首页，不放大面积设备仪表盘。连接异常用一条短提示承载，点入设备页；手机已保存内容在眼镜断连或服务器离线时仍可浏览。媒体播放控制只控制回放，不是采集命令。

**当前可用性规则：** 下表列成品目标操作，不代表目前已经可用。正式本地业务、真实传输/上传、照片与原厂视频导入分别须在对应 G 阶段接线验收；在此之前的规格/样稿只显示“待核查 / 未接入 / BLOCKED”及原因，不提供可点击的假入口。列表或详情已有真实可读文件时，可按其实际能力独立提供浏览/回放。

**范围规则：** 搜索、标题编辑和手机远程控制仍是候选能力；手工会话关联保留 G4 的可选性质。认可页面视觉方向不等于批准这些能力全部实施，也不把它们升为首版放行条件。没有确认范围或可用接线时，页面保留真实默认标题/未关联等基础行为，候选入口不启用；任务范围仍以对应 G 文件及用户后续决定为准。

### 2.2 U1 / U2：如何组织一条记录

2026-09-24对象表达修订：全部页明确会话卡片与未关联媒体的区别；会话摘要按实际本机条目显示录音/照片/视频的非零数量，注明“本机已列出”，不等于可播放、完整采集或交付成功。U2承接同一内容摘要；录音筛选直接打开单媒体详情。无可信日期时明确列表不代表时间先后，不用列表序号或猜测标题作身份。实现已做定向实测，外观仍待用户审阅。

| --- | --- | --- |
| 全部中的会话记录 | U2 本次会话详情 | 时间＋媒体数量，明确这是一次记录 |
| 录音/照片/视频筛选中的单个媒体 | 对应 U3/U4/U5 | 录音标题/时长或媒体缩略图；不先绕进会话 |

| 必要清理失败                   | **隐私未完成**           | “清理失败”；即使控制/原因行被手势占用，状态行仍保留此异常；资源停止也未确认时优先“停止未确认”                                             |
| 恢复请求已发出 / 已接收但未开始执行      | **保持可证的实际状态**       | 控制/原因行“恢复请求中 / 已接收”，分别依据发出与接收回执；仅仍可确认停止时保留“本应用隐私”，结果与资源状态无法确认则状态行“状态未知”                       |
| 恢复已明确确认、执行中              | **正在恢复**            | 成功后进入 A1；失败保留隐私意图并说明原因，若补偿停止未确认则显示“停止未确认”，不先显示录音中或隐私成功                                        |
| 确认异常停止                   | **记录已停**            | “权限已撤销”“空间不足”等可证原因；不自动循环拉起                                                                    |
| 真实状态缺失/不可确认              | **状态未知**            | 不沿用旧 A2 文案；仍应有尽力请求停止的入口，不能因未知而封死隐私控制                                                          |

电量只显示可信本机眼镜值；不可得或过期在电池图标后显示 `：—`。待迁移前手机持有的旧值不能冒充本机值。示意数字（包括用户图中的占位百分比）不是设备事实，不得硬编码。当前未知文案显示为“状态机：未知”。

状态行冲突优先级：停止未确认 → 状态未知/已知中断 → 隐私清理失败 → 必要的停止/恢复过渡 → 其他已确认采集状态。会话待结束、保存和收尾仅占第三行；照片暂停仍与实际录音状态一起表达。原厂系统提示保留，本 App 不盖住或压制它。优先级只决定展示，不改变策略或资源优先级。

### 4.3 停止与恢复：一页操作规则

**已确认：后滑进入本应用隐私；前滑累计填满进度条请求恢复，可连续或分次补满，不加单击。** 仅作用于本 App 前台可见且可接收输入的页面，不承诺后台全局手势。后滑停止仍须单独核验。

恢复条采用原生横向进度条、四段固定刻度和输入驱动动画。有效方向DOWN预览25/75，配对UP推进50/完成；两对可在一笔内出现，也可跨组补齐，不要求四次滑动。DOWN预览不增加已确认累计、不续期，不证明手指位移；快事件连续过渡，不强行停留刻度。**满格由输入逻辑判定，日志成功/业务回执决定结果，动画不得发命令。** 抬手/尾键不补满，开始键不加累计，未满允许6秒内续滑。界面用“向前滑动 / 继续滑动 / 已完成”等短文案，不显示0/2计数。试用页始终标明“不采集”，产品页须显示真实执行状态。

| 你做什么 / 当前情况 | 操作与提交规则 | 你会看到什么 |
| --- | --- | --- |
| 打开 App 或常态单击 | 只展开控制；点击打断未提交累计时清空，不发停止/恢复 | 真实状态＋后滑进入隐私/前滑恢复 |
| 前台后滑，包括 HUD 收起、未知/异常、恢复中 | 开始反向即取消未提交恢复累计；完整后滑请求停止，无额外单击，停止入口不被恢复锁挡住 | 未提交保留真实状态；发出后停止请求中，接收后停止中 |
| A0 中前滑，进度未满 | 有效输入累加；抬手后可继续，试用最后有效推进后6秒清零 | 进度停在已达位置，提示继续前滑；不显示正在恢复 |

| 重复按键 / 满格后的同组余下事件 | 不加格、不续期、不重复提交；记录真实结果不制造第二次操作 | 不重复弹结果、不重复启动 |

| 恢复已提交时再完整后滑 | 新停止意图优先，旧恢复结果不得越过新隐私身份；取消进度不撤销已发命令 | 以最新真实停止结果为准 |
| 停止失败/未知后再完整后滑 | 显式重试，关联同一隐私意图，业务幂等；执行中不并发重复 | 停止中/停止未确认/隐私未完成 |
| 已完整生效 A0 再后滑 | 幂等维持隐私，不重复已完成清理 | 本应用隐私 |

| 双击 | 交给已核验平台导航，本 App 不附带停止/恢复；已经发出的命令不因退出撤销 | 退出不代表采集停止，固件强停另记中断 |

**停止确认：** 已用资源停止和必要清理均确认才显示本应用隐私；已停但清理中、清理失败和停止未确认分别展示，不放恢复。G0的2秒初始反馈阈值不是允许继续录音的时间；无法交付停止请求时显示未知/请求未确认。

**恢复失败：** 启动/持久化失败维持隐私意图并补偿停止；补偿未确认显示停止未确认，不伪报安全A0。原请求不自动重试，用户须重新填满进度，业务重新校验。

**时限与取消：** 用户选定6秒停手清零试用，诊断用最后有效方向配对UP的本机uptime续期；首个起点/未配对输入也有有限期。新起点不延长已有累计，重复键、尾键、重绘/订阅不续期。移除旧800ms空闲及3s整次限制；保留过期/来源/配对、epoch与生命周期检查。不把控件收起时间、业务确认时间和输入时限混用；最终格数/时限由G0-07.4校准，G0-14/15冻结。

**输入与动效：** 复用旧分支setProgress(value,true)，仅向输入产生的目标值过渡。四段反馈不是四次实体滑动或连续坐标，不由动画自动填满或提交。保留累计、取消、旧事件隔离及业务guard；手机SeekBar二次确认不继承为眼镜操作。
